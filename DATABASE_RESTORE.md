# Восстановление ClashInfoBot из копии от 8 июня 2026 года

Бот использует восстановленную БД `clashinfobot_restored_20260608` в собственном
PostgreSQL-контейнере. Прежняя пустая БД `clashinfobot` сохранена как rollback.
Данные других проектов из архива не восстанавливались; Mindflower, RAID GAME,
Caddy, их контейнеры, конфигурация и базы не изменялись.

## Источник и сохранённые данные

Источник: `~/Downloads/cloudtube-bot-prod.zip`, вложенный архив
`vps-recovery-20260608T203400Z.tar.gz`, файл
`logical-dumps/clashinfobot-db-pg_dumpall.sql`. SHA-256 вложенного архива
проверен по приложенному checksum. SQL ClashInfoBot: 5 265 345 bytes,
SHA-256 `7b8e1daea16c9dc0a865aaf6113fe8b8ab278b396bced776bf7c114c49a593f8`.

| Данные | Строк |
| --- | ---: |
| Пользователи | 13 |
| Кланы | 5 |
| Доступы / заявки | 7 / 2 |
| Игроки / состояния в кланах / профили | 366 / 366 / 32 |
| Снимки состава | 1551 |
| Отчёты / строки игроков в отчётах | 57 / 2679 |

Все 52 записи отправки имеют статус `sent`; статусы и ключи дедупликации сохранены.
База содержит данные на момент копии, а не события после 8 июня.

## Выполненные проверки

1. Выбран только раздел БД ClashInfoBot. Глобальные роли, пароли и команды
   создания других БД из `pg_dumpall` не применялись на VPS.
2. Дамп восстановлен локально в контейнере без сети и host mounts, с временным
   PostgreSQL-хранилищем, непривилегированным пользователем и лимитами ресурсов.
3. Ревизия — `0007_user_language`. Нормализованный schema-only dump полностью
   совпал с отдельной свежей БД, созданной текущими миграциями.
4. Код приложения прочитал пользователей и все 7 доступов, подготовил 14 меню
   через mock и сформировал 114 представлений сохранённых отчётов на EN/RU.
   Telegram-сообщения при проверке не отправлялись.
5. На VPS передан только очищенный custom dump — 260 364 bytes. SHA-256:
   `d8837ac5af0bda2f4aeef5c519d59ecab9d076b43447ab536ba2c93b51539b40`.
   Он восстановлен одной транзакцией в новую БД, без импорта старых owners/ACL.
6. Все 13 таблиц, включая Alembic revision, совпали с проверенным источником
   по количеству строк и полным отпечаткам содержимого. Все 12 serial sequences
   проверены относительно максимальных ID.
7. Перед переключением остановлен только ClashInfoBot, подтверждена пустота
   прежней БД и создана шифрованная копия с отдельным restore-test; копии и proof
   сохранены на Mac с проверкой SHA-256.
8. В production `.env` изменены только `POSTGRES_DB` и имя БД в `DATABASE_URL`.
   Ключи, пароли, image, расписание и код приложения сохранены.
9. После переключения выполнен новый шифрованный backup и успешный restore-test.

`alembic check` обнаружил прежнее различие между ORM и миграцией: модель описывает
unique constraint для `outbox_messages.dedupe_key`, а миграция создаёт unique index.
Уникальность обеспечивается в обоих случаях. Это же определение индекса присутствует
в свежей БД из текущих миграций; полный schema comparison подтвердил совпадение.
Схема и миграции при восстановлении не менялись.

## Место, резервные копии и откат

Восстановленная БД занимает около 12 MiB. Каталог PostgreSQL вырос примерно
с 47 до 75 MiB, включая WAL и сохранённую прежнюю БД. Полный серверный архив
и volumes на VPS не копировались.

Исходный дамп, очищенный dump, локальные проверки и pre-cutover копии находятся
в `~/.local/share/clashinfobot/restore/` на Mac с закрытыми правами. Новый
зашифрованный backup хранится также в `~/.local/share/clashinfobot/backups/`.
Отдельный backup key — в `~/.config/clashinfobot/backup.key`.

Production env до переключения: `/opt/clashinfobot/rollback/restore-20260608/.env.before`,
права 0600. Для аварийного отката остановить только ClashInfoBot, вернуть имя БД
`clashinfobot` в двух указанных полях окружения и пересоздать только его db/bot.
Восстановленную БД не удалять: обе версии данных остаются доступны.

Текущее подтверждённое состояние — в `restore-20260608-checkpoint.json` в
`~/.config/clashinfobot/` на Mac и `/opt/clashinfobot/ops/` на VPS.
