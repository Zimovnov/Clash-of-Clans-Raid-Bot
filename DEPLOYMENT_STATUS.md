Рабочий релиз — `20261118-public-users`. Через настоящий диспетчер проверены
регистрация, языки, заявка, одобрение, отчёт и карточка игрока без админских прав.
Закрыта подмена ID чужого отчёта в трёх callback-обработчиках.
Полный набор: 76 тестов; все пять новых сценариев дополнительно прошли на локальной
PostgreSQL 16. Подробности: [PUBLIC_USERS_CHECK.md](PUBLIC_USERS_CHECK.md).

В релизе `20261118-access-requests` исправлены отказ суперадмину при
рассмотрении заявок без собственной роли в клане и отображение автора решения.
Полный набор: 71 тест; отдельно 10 сценариев на локальной PostgreSQL 16.
Схема, данные и DB container сохранены; контейнеры Mindflower не пересоздавались.
Подробности: [ACCESS_REQUESTS_CHECK.md](ACCESS_REQUESTS_CHECK.md).

## Фактические проверки

- 57 pytest-тестов прошли с фиктивными токенами и отдельной SQLite.
- Все 7 миграций прошли на отдельной локальной PostgreSQL 16, затем в новой серверной БД.
- Образ linux/amd64 собран на Mac; `pip check` прошёл.
- `pip-audit` зафиксированных runtime-зависимостей: известных уязвимостей не найдено.
- Docker-образ не содержит `.env`, `.git` и тестов.
- Все 62 Python-файла приложения и миграций совпали с содержимым образа по SHA-256.
- 75 файлов серверного source bundle проверены по manifest.
- API: `/ready` = 200, служебный POST без авторизации = 401, `/docs` = 404.
- С VPS успешно проверены Telegram `getMe`/`getWebhookInfo`, Clash locations,
  клан, участники, raid seasons и профиль игрока с реальным разбором ответа кодом приложения.
- В финальном контейнере один процесс бота, polling запущен, ошибок polling,
  перезапусков и OOM при проверке не обнаружено.
- ID контейнеров и счётчики перезапусков Mindflower сохранились относительно исходного среза.

- Шифрование, расшифровка и `pg_restore` копии в отдельном контейнере прошли;
  восстановленная ревизия — `0007_user_language`.
- Проверенный зашифрованный архив и JSON proof скопированы на Mac с проверкой SHA-256;
  независимая локальная копия backup key совпала с серверной.
- Ruff для новых operational scripts, shell syntax и `git diff --check` для
  изменённых Dockerfile/.dockerignore/pyproject.toml прошли.

## Исправления и ограничения

Для SQLAlchemy явно включён extra `[asyncio]`: без него новая SQLAlchemy 2.1
не устанавливала обязательный `greenlet`, и приложение не импортировалось.
Runtime-зависимости зафиксированы с hashes вместо свободного разрешения при каждой сборке.

Старый Clash API ключ возвращал `accessDenied.invalidIp`. Новый ключ для исходящего
IP VPS сохранён только в защищённых `.env` и успешно проверен. Токены в отчётах,
образе, source bundle и Git отсутствуют. `.env` и backup key имеют права 0600.

Проверка временной restore-БД ждёт окончательный запуск PostgreSQL по TCP:
временный Unix socket при инициализации не означает готовность к восстановлению.

Архив с Windows содержал незакоммиченные изменения; они сохранены. Commit и push
не выполнялись. Общий Ruff выявил 89 существовавших замечаний в исходниках;
Windows line endings также дают прежние замечания общего `git diff --check`.
В pytest остаётся предупреждение Starlette о будущем переходе test client на httpx2.

В первом архиве не было дампа прежней БД; первоначально установка была пустой.
Позднее история восстановлена, как указано выше. Ручных тестовых Telegram-сообщений не отправляли; фактически проверены
polling и API, а сценарии команд покрыты локальными тестами.
Автоматический off-host backup не настроен; на Mac сохранена первая проверенная копия.

Санитизированный operational checkpoint: `~/.config/clashinfobot/deployment-checkpoint.json`
на Mac и `/opt/clashinfobot/ops/deployment-checkpoint.json` на VPS.
