# Доступ обычных пользователей

В релизе `20261118-public-users` проверен полный путь новых пользователей без
superadmin. Новые Telegram ID регистрируются автоматически; username необязателен.
Для существующего клана доступ появляется после решения owner или другого
разрешённого правилами reviewer. Административные команды обычным пользователям
не выдаются.

## Фактические проверки

Через `Dispatcher.feed_update`, production routers и middleware прошли сценарии
на EN/RU: `/start`, смена языка, подключение нового клана, пустой список кланов
нового пользователя, подача заявки, отказ в самостоятельном её одобрении,
одобрение владельцем, список доступных кланов, построение отчёта, раздел игроков,
карточка и обновление профиля. Доступ к другому клану и `/transfer_owner` отклонён.
В одном сценарии участвуют три независимых пользователя и два клана.

Telegram API и Clash API в автоматических тестах заменены записывающим транспортом
и детерминированными данными. Полный pytest: **76 passed**. Оба обычных сценария
и три сценария подмены ID дополнительно прошли на отдельной локальной PostgreSQL 16.
Ruff smoke-тестов и `git diff --check` прошли. Предупреждение Starlette о будущем
test client осталось прежним; зависимости не обновлялись.

Выполнены read-only проверки production Telegram API: `getMe` = 200 и
`getMyCommands` для всех private chats = 200. Публичное меню содержит start, help,
english, russian, addclan, myclans, report.
Clash API с сервера также успешно вернул авторизацию, данные отслеживаемого клана
и его рейдов. Данные из этих read-only запросов не сохранялись в рабочую БД.

## Исправление изоляции отчётов

До исправления три отрицательных теста воспроизвели чтение чужого отчёта или
обращение к его профилю: callback проверял доступ к указанному тегу клана, но
не проверял связь переданного `report_id` с этим кланом. Исправлены обработчики
`report_cat`, `report_player`, `report_player_refresh`: чужой report_id теперь
возвращает локализованный ответ «отчёт не найден» до выдачи содержимого или
запроса профиля. Прямые команды и разрешённые кнопки своего клана продолжают работать.

Изменены три проверки в одном runtime-файле
`app/integrations/telegram/handlers/reports.py`. Схема и существующие данные не менялись.
Перед выпуском выполнены backup, отдельный restore-test и off-host сверка архива.
Rollback metadata: `/opt/clashinfobot/rollback/20261118-public-users/`.
Откат совместим с прежней БД: вернуть image и `current`, пересоздать только bot.

Operational checkpoints — `server-before.json` и `server-after.json` в
`~/.config/clashinfobot/releases/20261118-public-users/` на Mac и в соответствующих
каталогах rollback/release на VPS. Production-проверки не создают искусственных
пользователей и заявок и не отправляют тестовые сообщения реальным людям.
